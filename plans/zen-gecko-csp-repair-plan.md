# Gecko Companion CSP Repair Plan

Execution is underway. Keep all browser enforcement and process-monitor tests in the existing disposable macOS guest.

**Goal:** Restore authenticated loopback companion connections in Zen and Firefox without weakening script execution controls or changing Chromium/Safari behavior.

**Evidence:** See [the diagnosis report](zen-network-alternatives-report.md). Unmodified temporary add-ons requested `ws://127.0.0.1:1421/focus-browser`, but both Gecko consoles showed failed `wss://` connections. A guest-only copy that added `content_security_policy.extension_pages: "script-src 'self'; object-src 'none';"` connected as Zen and Firefox and ACKed. This broad experiment is not the proposed production policy. Mozilla documents the default MV3 `upgrade-insecure-requests` behavior in its [CSP guidance](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Content_Security_Policy#upgrade_insecure_network_requests_in_manifest_v3).

## Files and boundaries

- Modify `extensions/firefox/manifest.json` only if the guest checks below prove the candidate CSP works. Keep `script-src 'self'` and `object-src 'none'`; do not enable remote scripts, inline code, or `unsafe-eval`.
- Use `extensions/focus/background.js::connect` unchanged: it constructs `ws://127.0.0.1:${port || 1421}/focus-browser`. The server remains loopback-only and authenticated. `port` is configurable, so the policy must not accidentally pin 1421.
- The existing `extensions/tests/desktop-bridge.test.mjs` runs Chromium, not installed Firefox or Zen. Do not claim it covers Gecko and do not weaken or replace it.

### Mozilla consent preparation

- `background.js` reads open tab URLs locally and redirects blocked existing tabs to an extension page; source inspection does not show those visited URLs sent to the desktop bridge. Mozilla classifies visited URLs/domains as `browsingActivity`, but whether this local handling requires declaration is unresolved.
- `native-pairing.js` sends a connect request and receives a local pairing token and port; `bridge-auth.js` sends a nonce and proof, with profile ID, browser identity and installation metadata. Authenticated heartbeats and ACKs include profile ID and revision; errors can include API error text. The blocked-domain policy flows from the desktop to the extension. HMAC authentication does not encrypt frame payloads.
- Browser/install metadata and errors are candidates for `technicalAndInteraction`; Mozilla makes that built-in category optional. Classification of the persistent profile ID, pairing token/proof, essential loopback metadata, and user-selected blocked domains is not established. Do not assert `none` or classify essential traffic as optional without a compliant user choice.
- Mozilla's [taxonomy](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/) and [data-transmission policy](https://extensionworkshop.com/documentation/publish/add-on-policies/#data-collection-and-transmission-disclosure-and-control) apply to data sent to native applications. Built-in consent starts with desktop Firefox 140; this extension's minimum is 115, so any applicable older-version consent requirement also needs resolution. The owner or Mozilla must determine the exact categories and consent behavior before signing.
